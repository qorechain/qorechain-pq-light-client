# Test vectors

`pq-light-client-v1.json` is shared by the Go, Rust and TypeScript verifiers. It is generated by `scripts/gen-vectors.mjs`, a deterministic simulator: keys come from fixed test seeds (`SHAKE-256("qorechain-pqlc-test-seed-v1|" + label + "|" + index)`) and ML-DSA-87 signing is deterministic, so regenerating gives the same file byte for byte. **The keys are public test keys.**

```bash
(cd ts && pnpm install --frozen-lockfile && pnpm build) && node scripts/gen-vectors.mjs
```

## Layout

All 64-bit integers are decimal strings; all bytes are lowercase hex.

| Key | Contents |
|---|---|
| `constants` | signing and hash domains, sizes, limits |
| `validatorSets` | id to `{ encoded, hash, validators, totalPower }` |
| `signedCheckpoints` | id to `{ encoded, signBytes, epoch, height, signers }` |
| `trustRoots` | id to `{ checkpoint, validatorSet, nextValidatorSet, trustingPeriod, maxClockDrift }` |
| `cases` | the cases below |

Every implementation decodes each validator set and signed checkpoint, re-encodes it to the same bytes and checks the hash and the sign-bytes.

## Cases

- `chain`: build the trusted state from `trustRoot` (`newTrustedState`), then apply `steps` in order with `verifyCheckpoint(state, checkpoint, now)`. A step expects either `{ ok: true, epoch, height, validatorSetHash, nextValidatorSetHash }` of the new state, or `{ ok: false, error }`; a failed step leaves the state unchanged. `CONFLICTING_CHECKPOINT` steps also give the expected evidence.
- `misbehaviour`: `detectMisbehaviour(validatorSet, a, b)` returns the expected evidence or nothing.
- `decode`: the `object` (`checkpoint`, `validatorSet` or `signedCheckpoint`) either decodes and re-encodes to the same bytes, or fails with `MALFORMED`.

## Scenarios

- 4 validators, powers 100, 100, 50, 50 (chain `qorechain-sim`); rotation at epoch 2: one validator leaves, a new one joins with power 60.
- 21 validators, powers 50, 55, ..., 150 (chain `qorechain-sim-21`); rotation at epoch 2: the three largest leave, three new ones join with power 100.

Rejections covered: exactly two thirds of the power, tampered height, flipped signature byte, wrong chain id, signature by a removed validator, the outgoing set after a rotation, a skipped rotation, a next set that does not match its hash, a set the trusted state does not name, replay, non-increasing height, expired trust, a checkpoint from the future, conflicting checkpoints, and every structural decoder rule.
